# Збій `Sandbox produced protected file content`

Причина: після `npm install` синхронізація workspace перевіряла код функцією маскування термінальних логів. Вона спрацьовувала на звичайні TypeScript-поля `password: string` і `token: string` у `npati-client.ts` та компоненті авторизації. Агент отримував помилку build і повторював спроби ремонту, хоча проблема була в перевірці синхронізації.

У `ProjectSandboxService` змінені й нові файли тепер перевіряє сканер секретів вихідного коду та перевірка літеральних credentials. Незмінені канонічні файли не перевіряються маскувальником логів. Значення з vault блокуються в усіх файлах, включно з manifest/lockfile. Перевірки шляхів, RBAC і revision guard збережені.

Локальний API і company-worker перебудовано та оновлено. Реальний запит через вебмаршрут `/api/chat/stream`, із сесією власника інсталяції та підключеною моделлю:

> Створи тестовий сайт інтернет магазин на Next.js, запусти build і Live Preview

Результат 09.10.2026: 156 секунд до відповіді чату, проєкт `919471bc-ca2b-4e3a-b38f-45aff1881b88`, запуск `9f2672c5-8d86-43b9-895f-6a3d1ff9c367`. `npm install` — 38,7 с; `npm run build` — 47,4 с, exit code 0. Картка: `previewing`, `Build: success`. Окремий HTTP-запит через web → API → runtime повернув 200 і HTML Next.js (11 047 символів). Новий Docker-контейнер для проєкту не створювався.

Цей тест підтверджує створення, production build і Preview; він не підтверджує кожну бізнес-функцію магазину або всі зміни, описані моделлю у текстовій відповіді. Перший запуск усе ще витрачає час на відповідь моделі, встановлення залежностей і production build.

Повторний реальний тест створив проєкт `1a2455b0-c2f3-4633-8d1f-4a502a4f2fd2`, але його видалили через локальний вебінтерфейс під час build (`DELETE` о 13:58:20 UTC). Це не успішний повторний тест. Виявлено додатковий дефект: orchestrator намагався створити repair run після видалення проєкту, отримуючи помилку зовнішнього ключа. Додано повторну перевірку існування/архівування проєкту перед ремонтом: видалений проєкт завершує запит із `PROJECT_REMOVED`, без repair run. Окремий тест відтворює видалення під час build. 55 цільових тестів пройшли; typecheck API і lint також пройшли.

Після фінального оновлення API повторний запуск Preview першого тестового сайту повернув `Project has no attached DataBackend`: під час тестування через вебінтерфейс також видалили DataBackend. Видалену базу автоматично не відновлювали. Зазначений вище HTTP 200 зафіксовано до цих видалень; це не твердження, що старий тестовий сайт залишається працездатним після видалення його бази.

Для повторної повної перевірки скопіювати `scripts/verify-chat-website.cjs` у `/app/verify-chat-website.cjs` контейнера `npati-agent-api` і виконати `node /app/verify-chat-website.cjs`. Скрипт створює один новий тестовий сайт, перевіряє результат SSE, build event і реальний HTTP Preview; токени не виводить. Копіювати файл через `docker cp`, щоб PowerShell не змінив кодування українського запиту.

# Виправлення магазину та відповіді в чаті — 09.10.2026

Причина простого екрана: Data Studio bootstrap замінював головну сторінку Next.js обгорткою `ProjectStore`. Дизайн у `website.config.json` не відображався. У перевіреному користувацькому проєкті конфігурація також залишалася шаблоном платформи, хоча відповідь моделі описувала інші зміни.

Виправлення:

- Головна відображає блоки документа й підключений до Project API каталог замість тарифів. Початковий шаблон магазину містить навігацію, головний блок, каталог, кошик і справжню форму звернення.
- Bootstrap адаптує згенеровану головну сторінку; повторний запуск зберігає окрему користувацьку сторінку. Зміни теми документа застосовуються на головній.
- Каталог отримує товари з бази, підтримує пошук, стани завантаження та помилки, форматує гривні. Кошик і checkout зберігають наявні SDK/RLS-механізми.
- Успішна відповідь формується зі стану виконання, без технічного есе моделі. Старі довгі повідомлення з успішною карткою також відображаються стисло. Помилки й погодження залишаються видимими; результат моделі залишається в Activity.
- Preview маршрутизує посилання після React hydration та клієнтські fetch/history-запити. Запити Project API та зовнішні адреси не отримують Preview-токен.

Локальні API, company-worker і web перебудовано й запущено. Runtime та схему контейнерів не змінено. Виправлено наявний проєкт `20bbc363-fb2d-4e38-9095-9d9281da9c46` через API запису файлів із revision guard; дані бази збережено.

Перевірка через справжній браузерний чат із підключеною моделлю: проєкт `98a0f9d8-974c-48e5-9b78-b0e5cf18fd6b`, run `9d6df601-21f1-44a1-aa14-d939169c6326`. Production build успішний. Кнопка Preview відкрила сайт; перевірено пошук, повідомлення про необхідність входу перед додаванням у кошик, авторизаційну сторінку, повернення на головну та ширину 390 px без горизонтального переповнення. Увесь сценарій з додатковими переходами й скриншотами — 133 секунди, це не окремий замір часу до першого Preview.

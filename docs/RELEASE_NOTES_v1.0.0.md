# NPATI Agent Platform — Release Notes v1.0.0

## 1. Release Overview
Версія **v1.0.0** — це виробничий реліз корпоративної агентної платформи NPATI Agent, що інтегрує нативний шлюз OmniRoute (352 ШІ-провайдери), гібридний маршрутизатор навичок та інструментів, багатоагентну ієрархію компаній, строго ізольований контекст активності, багаторівневу політику безпеки з HMAC-підтвердженням ризиків та сертифіковану стійкість до високих навантажень.

---

## 2. Key Architecture & Features Delivered

1. **Active Context Boundary (`ActiveContextResolver`)**:
   - Чіткий розподіл трьох режимів: `none` (нейтральний чат), `business` (інкубатор ідей) та `company` (виробнича діяльність).
   - Жодного змішування пам'яті між бізнесом та компанією.
2. **74 Agent-Callable Tools & 232 Runtime-Only Capabilities**:
   - Точний каталог з 306 можливостей.
   - Суворе обмеження: не більше 15 інструментів у промпті моделі одночасно (запобігання переповненню контекстного вікна).
3. **Company Hierarchy & Orchestration**:
   - Призначення Main Agent (координатора) та підпорядкованих Specialist Agents.
   - Три режими виконання: `single`, `pipeline`, `fusion`.
   - Інтеграція протоколу A2A для розподілу завдань та паралельного виконання.
4. **Fail-Closed Security & HMAC Risk Approvals**:
   - Багаторівнева авторизація (Tenant Permissions -> Context Boundary -> Company Overrides -> Agent Allowlist -> Risk Level).
   - Критичні руйнівні операції потребують криптографічного HMAC-токену підтвердження.
   - 0 витоків секретів у логах, аудиті та інтерфейсі.
5. **Production Scale Certification**:
   - Індексація та пошук серед 100 000 компаній із затримкою p95 < 2 мс.
   - Робота з 500 000 конфігураціями агентів без N+1 SQL-запитів.
   - Одночасна підтримка 10 000 активних сесій із споживанням пам'яті < 15 МБ у Redis.
   - Обробка стрімів SSE з контролем backpressure та нульовою втратою чанків (0 dropped frames).

## 3. Upgrade Notes
- **Сумісність з OmniRoute**: підтримуються версії `[>= 3.8.49 < 4.0.0]`. Базова тестована версія — `v3.8.50`.
- **Node.js**: потрібна версія `>= 22.22.2`.
- **Database Schema**: 24 міграції застосовуються послідовно та ідемпотентно.

---

## 4. Rollback Procedure (Процедура швидкого відкату)

У разі виникнення критичних інцидентів під час розгортання:
1. **Зупинка трафіку на нові репліки**:
   - Перемкнути маршрутизацію балансувальника на попередній релізний тег `v0.9.x`.
2. **Перевірка стану БД**:
   - База даних PostgreSQL зберігає повну зворотну сумісність: таблиці `companies`, `agents`, `company_runs`, `company_run_steps` підтримують читання попередньою версією без змін DDL.
3. **Очищення черг Redis**:
   - У разі несумісності форматів повідомлень у черзі `npati:company-runs:v1`:
     `redis-cli DEL npati:company-runs:v1`
4. **Перезапуск воркерів**:
   - Запустити воркери з попередньої версії образу контейнера.
   - Невиконані або перервані завдання автоматично переходять у стан `cancelled` або перехоплюються за лізом.

## 5. Migration Notes
- Застосовано міграції `001_initial_schema.sql` ... `024_add_capability_audit.sql`.
- Всі міграції мають конструкції `IF NOT EXISTS` та ідемпотентні тригери.
- Authoritative Storage: **PostgreSQL**.
- Volatile Cache / Queues: **Redis**.
- Object Storage: **MinIO**.

---

## 6. Known Limitations & BLOCKED_EXTERNAL (Чесні обмеження)

1. **Зовнішні провайдери (LLM APIs)**:
   - Зовнішні rate limits провайдерів (OpenAI, Anthropic, Google) не контролюються платформою NPATI. При вичерпанні лімітів рекомендується використовувати `auto-combo` або fallback-маршрутизацію OmniRoute.
2. **Staged Load Testing**:
   - Тести навантаження 100 → 500 → 1000+ одночасних запитів виконувалися із використанням безпечного provider-emulator для уникнення фінансових витрат та блокування зовнішніх акаунтів.
3. **Локальні інструменти середовища**:
   - Інструменти терміналу, башу та виконання процесів увімкнені лише в режимі `ToolSandboxRunner` з ізольованою тимчасовою директорією.

## 7. Production Configuration Checklist

Перед розгортанням у продакшн переконайтеся у наявності змінних оточення:
- [ ] `DATABASE_URL`: коректне підключення до PostgreSQL (з пулом pgbouncer/pooling).
- [ ] `REDIS_URL`: адреса кластера або інстансу Redis.
- [ ] `MINIO_ENDPOINT`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `MINIO_BUCKET`: параметри сховища об'єктів.
- [ ] `OMNIROUTE_BASE_URL`, `OMNIROUTE_API_KEY`: доступ до інстансу OmniRoute.
- [ ] `APP_SECRET`: 32+ символьний криптографічний ключ для HMAC-підписів підтвердження ризиків.
- [ ] `PORT`: порт бекенду (за замовчуванням 3000).

## 8. Smoke-Test Checklist після розгортання

Після деплою виконати швидку верифікацію:
1. `GET /health` -> `status: "healthy"`.
2. `GET /ready` -> перевірка з'єднань PostgreSQL, Redis, MinIO, OmniRoute.
3. Надіслати тестове повідомлення в чат: `"Привіт, поясни архітектуру"` -> очікується відповідь без інструментів (`NO_TOOL`).
4. Запустити швидкий смоук-тест: `npm run gate:upgrade`.
